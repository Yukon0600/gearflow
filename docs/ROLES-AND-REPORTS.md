# 角色权限与经营报表

## 角色模型

账号表 `users` 增加 `role` 字段，三个角色：

| 角色 | 代码 | 定位 |
| --- | --- | --- |
| 管理员 | `admin` | 系统负责人，能管账号 |
| 店长 | `manager` | 负责商品资料、往来单位、员工与报表 |
| 店员 | `clerk` | 日常开单、盘点、查数据 |

老库升级时 `role` 默认填 `admin`，避免把自己锁在门外。

## 权限判定

后端不按接口一个个声明权限，而是用一条规则函数统一推导（见 `apps/server/src/permissions.ts`）：

```ts
requiredRole(method, path)
  /api/users*    → admin
  /api/reports*  → manager
  GET / HEAD     → clerk      // 读操作店员即可
  /api/orders、/api/drafts*、/api/stocktakes → clerk   // 开单与盘点
  其余写操作      → manager    // 商品、往来单位、员工、服务
```

请求进来后，认证中间件拿到 `user.role`，`canAccess()` 比较等级，不足直接 `403`，并回一句人话：`当前为店员，没有该操作权限`。

前端不重复实现规则，只消费 `/api/auth/me` 返回的 `abilities`，并按 `nav.minRole` 过滤菜单：
店员看不到「经营报表」和「用户权限」，`新建商品` 按钮也被隐藏；即使绕过界面直接调接口，后端同样 403。

## 账号管理约束

- 账号 3–32 位，仅字母、数字、下划线、点、短横线；
- 密码 8–128 位，scrypt 加盐存储；
- 不能删除自己，也不能把最后一个管理员降级或删除；
- 重置密码会让该账号所有在线会话立即失效（删除 sessions 记录）。

## 报表口径

`GET /api/reports/overview?days=7|30|90`，全部按单据行（`order_lines`）聚合：

| 指标 | 计算方式 |
| --- | --- |
| 销售额 | 销售单行 `quantity × unitPrice` 求和 |
| 采购额 | 采购单行同上 |
| 毛利 | 销售行 `(unitPrice − 商品当前成本) × 数量` |
| 毛利率 | 毛利 ÷ 销售额，以万分比存储，前端除以 100 显示 |
| 客单价 | 销售额 ÷ 销售单数 |
| 库存占用 | `SUM(stock × cost)`，当前时点快照 |
| 趋势 | 按 UTC 日期分组，缺失日期补 0，保证 7/30/90 天曲线连续 |
| 商品排行 | 按销售金额排序取前 8，附件数与毛利 |
| 品类占比 | 分类销售额占比，前 6 类 + 「其他」 |

**已知简化**：毛利用的是商品**当前**成本，不是出库时的成本快照。若商品成本被修改，历史毛利会跟着变。
要做到严格口径，需要在 `order_lines` 里落一份成本快照——这是下一步可以补的点，答辩时可以主动说明。
