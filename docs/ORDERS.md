# 单据体系

## 五种单据

| 类型 | 代码 | 单号前缀 | 库存 | 往来单位 |
| --- | --- | --- | --- | --- |
| 采购入库 | `purchase` | `PO` | ＋ | 供应商（必填） |
| 销售出库 | `sale` | `SO` | － | 客户（必填） |
| 销售退货 | `return_in` | `RI` | ＋ | 客户（必填） |
| 采购退货 | `return_out` | `RO` | － | 供应商（必填） |
| 报损 | `scrap` | `SC` | － | 内部损耗（选填原因） |

老库只有采购与销售两种，`orders` 表带 `CHECK` 约束，SQLite 无法直接改约束，启动时检测到旧结构会**重建表**（关闭外键 → 建新表 → 拷贝 → 改名 → 恢复外键），历史单据原样保留。迁移已在生产数据副本上验证：49 张单据迁移后仍是 49 张。

## 库存与金额规则

- 入库类（采购、销售退货）加库存，其余减库存；
- 减库存的单据统一校验「可用库存 ≥ 数量」，不足直接 409，事务回滚；
- 每行都落 `unitCost` 成本快照：采购行用进价，其余用当时商品成本。

## 报表口径

| 指标 | 计算 |
| --- | --- |
| 销售额 | 销售 − 销售退货 |
| 采购额 | 采购 − 采购退货 |
| 毛利 | Σ 销售 `(售价−成本)×数量` − Σ 销售退货 `(退款−成本)×数量` |
| 报损 | Σ 报损 `成本×数量`，单独一列，不冲减销售额 |

## 分页接口

`GET /api/orders?page=1&size=20&type=sale&q=单号或单位`
`GET /api/movements?page=1&size=20&q=商品或单号&direction=in|out`

返回 `{ page, size, total, pages, items }`，`size` 上限 100。越界页返回空数组而不是报错。

前端「库存流水」页已改为服务端分页 + 加载更多，避免一次拉全量；商品与单据列表数据量小，仍用前端分页。

## 小程序开单

支持一次添加多行商品：从库存页或详情页进入后，点「添加商品」从弹层选择，逐行改数量和单价，底部实时合计，提交时一次性 `POST /api/orders`（后端本来就支持多行）。
