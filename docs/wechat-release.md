## 一、体验版路线（最快：当天可扫码，限体验成员）

体验版**不需要审核**，把人加为"体验成员"后，扫体验二维码即可使用。适合先给店长/店员用起来。

### 第 0 步：注册正式小程序账号（一次性，约 10 分钟）
测试号只能自己调试，要给别人用必须注册正式账号：
1. 打开 [https://mp.weixin.qq.com](https://mp.weixin.qq.com) → 右下角「立即注册」→ 选「小程序」。
2. 主体选择：
   - **个人主体**（推荐先走这条）：免费、只需身份证+手机号+未注册过小程序的邮箱。适合先给店里几个人用起来；个人号不能开通支付，但进销存内部工具够用。
   - 企业/个体工商户主体：需要营业执照，后续可开微信支付、认证费 300 元/年。正式商用再升级（账号信息可在「设置」里做主体变更，但流程繁琐，建议一开始就定好）。
3. 注册完成 → 登录后台 →「设置 → 基本设置」完善名称（如 GearFlow 进销存）和头像。
4. 「开发 → 开发管理 → 开发设置」复制 **AppID**（18 位）→ 填入 `apps/uni-mobile/src/manifest.json` 的 `mp-weixin.appid`，替换测试号 ID。
5. 同页「小程序代码上传」→ 生成**代码上传密钥**并记下 IP 白名单要求（开发者工具上传时若要求配置，按提示加白本机公网 IP，或暂时关闭 IP 白名单强制校验）。

### 第 1 步：确认小程序账号与 AppID
1. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com)（小程序账号，非公众号）。
2. 「开发 → 开发管理 → 开发设置」查看真实 AppID（18 位，形如 `wx` + 16 位）。
3. 把真实 AppID 填进 `apps/uni-mobile/src/manifest.json` 的 `mp-weixin.appid`。

### 第 2 步：重新构建小程序
```powershell
cd C:\企业信息管理系统\apps\uni-mobile
npm run build:mp-weixin
```
产物在 `dist/build/mp-weixin`。若报 `winmm.dll not found`，见 README「疑难排查」章节。

### 第 3 步：微信开发者工具上传
1. 打开「微信开发者工具」→ 导入项目 → 目录选 `dist/build/mp-weixin`，AppID 填真实值。
2. 右上角「上传」，填版本号（如 `1.4.0`）和备注（如"单据中心+盘点+应收应付"）。

### 第 4 步：添加体验成员并发体验码
1. 小程序后台「管理 → 成员管理 → 体验成员」→ 添加使用者的微信号。
2. 后台「版本管理 → 开发版本」→ 找到刚上传的版本 →「选为体验版」→ 生成**体验版二维码**。
3. 把二维码发给体验成员，扫码即用。

### 第 5 步（域名备案期间临时）：绕过域名校验
体验版会校验 request 合法域名，而目前只有 IP 没有备案域名。临时办法（每个使用者操作一次）：
> 打开体验版小程序 → 右上角 `···` → **开发调试** → 打开调试模式（右下角出现 vConsole）→ 重进小程序即不校验域名。

⚠️ 这只是过渡方案。正式使用（含后续版本）必须完成域名备案。

## 二、正式发布路线（备案通过后）

### 第 1 步：域名与证书就绪
1. 备案通过后，确认 `https://timomo.store` 可访问（`infra/nginx.https.conf` 里有现成 HTTPS 配置）。
2. 建议用 Let's Encrypt 或阿里云免费证书。

### 第 2 步：改小程序后端地址并重新构建
`apps/uni-mobile/src/config.js`：
```js
const FALLBACK_BASE = 'https://timomo.store';
```
然后重新 `npm run build:mp-weixin` 并在开发者工具重新上传。

### 第 3 步：配置服务器域名（关键，不做小程序连不上后端）
小程序后台「开发 → 开发管理 → 开发设置 → 服务器域名」：
- **request 合法域名**：`https://timomo.store`

（小程序只发 request，不用上传/下载域名的可留空。每月可改 5 次。）

### 第 4 步：重新部署服务端（确保功能完整）
本地 `GET /api/drafts` 是新加的，线上服务器需更新：
```powershell
# 在服务器上（或按 infra/deploy.sh 的流程）
cd /opt/gearflow && git pull && docker compose -f infra/docker-compose.prod.yml up -d --build server
curl -k https://127.0.0.1/api/health
```
（也可以走国内 Gitee 镜像仓库中转。）

### 第 5 步：提交审核 → 发布
1. 后台「版本管理 → 开发版本」→「提交审核」。
2. 审核信息填写建议：
   - **服务类目**：企业主体选「IT科技 → 基础电信服务/软件提供商」或「商业服务 → 企业管理」类目（按账号实际可选类目为准）；个人主体类目受限，建议用企业主体注册。
   - **功能页面**：选工作台首页，截图用库存/单据页面（避免出现测试数据）。
   - **说明**：如「GearFlow 企业进销存管理工具，用于库存、单据与往来账管理」。
3. 审核通过（通常 1~7 天）→「版本管理」→「发布」→ **正式版二维码**在「码搜索/二维码」处生成，任何人扫码即可使用，也可在微信内搜索小程序名称。

## 三、常见问题

| 问题 | 处理 |
|------|------|
| 手机上请求失败 / 域名不合法 | 检查「服务器域名」配置；体验期用调试模式过渡 |
| 审核被拒「个人主体功能不符」 | 进销存属企业服务，建议用企业/个体工商户主体注册小程序 |
| 上传时报 AppID 无效 | AppID 必须是 18 位且与登录开发者工具的微信绑定为该小程序的开发者 |
| 想要门店店员免注册直接用 | 小程序内已有账号密码登录体系，无需微信授权绑定，审核时说明即可 |
| 后端换 IP/域名 | 只改 `config.js` 的 FALLBACK_BASE 重新构建上传，同时在后台更新合法域名 |
